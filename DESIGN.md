# Design System — Conduit Console

Source of truth for every visual decision in `app/web/templates/` and the
stylesheet. The stylesheet implements these as CSS custom properties; later
slices consume them. Deviations need a note here, in the Decisions Log.

## Product context

- **What this is:** a self-hosted operator console for one Conduit Financial
  organization — onboarding, accounts, payouts, transfers, conversions, and an
  operations ledger.
- **Who it's for:** trained, daily, high-volume users — but not this
  organization's own staff. It is deployed to client organizations and used
  by their **treasury teams**: professional B2B financial software, closer to
  Modern Treasury or Kyriba than to consumer fintech. They did not choose
  this tool and cannot walk over to whoever operates the install to ask a
  question. (Arca direction, §0.3 — see below.)
- **Project type:** data-dense internal web app, server-rendered Jinja + htmx.
- **The memorable thing:** *the console never lies about the state of money.*
  Every design choice serves state legibility: what happened, what's pending,
  what needs a human.

## Aesthetic direction

**Amended 2026-09-03 (Arca).** The rules
below are the target; nothing here is rendered yet except Product context
above. Tokens, shell and templates land in A1–A5 (see the dated section
below and `docs/ARCA_REVAMP_SPEC.md`).

- **Direction:** function-first and data-dense stay — this is still
  professional treasury software, read by a trained daily user scanning
  hundreds of rows a session, not a consumer surface. The shell sits on a
  page ground: cards and trays read as objects on paper, not one white
  plane. Flat and quiet — near-zero radius outside the shell and the accent
  block, hairline dividers, no gradients, no shadow deeper than the existing
  hairline.
- **Decoration level:** unchanged — typography, spacing and one status-color
  system do all the work. No icons where a word is clearer.
- **Interaction color:** the accent is blue and means one thing — **you can
  act here.** Status hue is a separate vocabulary and means the state of
  money; the two are never the same hue (Arca drops `--processing`, the one
  color that collided with the accent). Color is never decoration.
- **Type:** Conduit's own faces — Founders Grotesk (heading, expected not
  yet vendored), DM Sans (body), JetBrains Mono (data) — **not** the spec's
  Bricolage Grotesque / Hanken Grotesk. Arca's own scale, weight capped at
  **500** everywhere. See Typography and the Decisions Log.
- **Modes:** dark mode ships alongside light, both from one token block.
  Reverses the 2026-08-29 "no dark mode in v1" row — see Decisions Log.
- **Navigation:** the left ribbon stays. The reference mockup's four-link
  top bar is rejected, not adopted — see Decisions Log.
- **Mood:** calm, precise, boring in the way a cockpit is boring. Color is
  *information*, never decoration: if something on screen is colored, it is
  telling you the state of money or a required action.

## Typography

Hard constraint, **amended 2026-08-31**: no *third-party-hosted*
fonts. The rule used to read "no webfonts, no vendored font files"; what it was
protecting was the app's ability to run offline with zero front-end
dependencies and to make no request off its own origin — not the absence of a
font file. A font served by this app from `static/fonts/` costs neither of
those, so an OFL-licensed face vendored into the repo is allowed. What stays
forbidden is unchanged and is the part that mattered: no `@import` from Google,
no CDN, no build step, no package. The licence ships with the files and the
provenance URLs are recorded in the `@font-face` comment in `static/styles.css`.

**Amended again 2026-09-02: the console is set in Conduit's own
type.** Read off `conduitpay.com`'s stylesheet
(`cdn.prod.website-files.com/…/conduit-stage.shared.0bc6f0dd2.css`), the site
declares exactly three families and the console now names the same three:

| Site token | Family | Here |
|---|---|---|
| `--font--heading-family` | **Founders Grotesk** (Klim, commercial) | `--font-heading` — **expected, not shipped** |
| `--font--body-family` | **DM Sans** (OFL) | `--font-ui` — vendored |
| `--font--mono-family` | **JetBrains Mono** (OFL) | `--font-mono` — vendored |

Archivo is gone, files and all.

- **Headings:** `--font-heading` = `"Founders Grotesk", "DM Sans", system-ui, …`.
  Founders Grotesk is **commercial and is not in this repo** — not downloaded,
  not copied from Conduit's CDN, not stood in for by a look-alike. Two
  `@font-face` rules name `static/fonts/founders-grotesk-regular.woff2` (400)
  and `-medium.woff2` (500) — the site's own filenames and the two of its three
  weights this console consumes — and until the licence holder drops those files
  in, the stack falls through to DM Sans and headings render in the body face.
  Dropping the files in is the whole deployment step; no code changes
  (`deploy/README.md` § Fonts). Consumers: `h1`, `h2`, `.ribbon .brand`,
  `.stat-band .figure`. **Nothing asks this stack for a weight above 500**: the
  family will ship 400 and 500 only, so a 600 or 700 request renders in DM Sans
  today and as *synthetic* bold the day the licensed files land — the stand-in
  this phase refuses, arriving by the back door.
- **Body/UI:** `--font-ui` = `"DM Sans", system-ui, -apple-system, "Segoe UI",
  sans-serif`. One **variable** woff2, loaded whole — no `unicode-range`, so the
  fallback boundary is the file's own cmap rather than a range this stylesheet
  asserts and could get wrong. That boundary is **Latin + Latin-Extended**
  (403 codepoints; no Cyrillic, Greek, Vietnamese or CJK) and it is upstream's,
  not a subsetting decision. `input, select, textarea { font: inherit }`, so the
  onboarding form's inputs are DM Sans and a name in a script it does not carry
  renders per-glyph in the system stack. `font-display: swap`.
- **Data (ids, references, amounts, bank coordinates, timestamps):**
  `--font-mono` = `"JetBrains Mono", ui-monospace, "SF Mono", …` at **weight
  500** with `font-variant-numeric: tabular-nums`. Monospace is still the
  console's signature: any value an operator might copy, compare or reconcile is
  set in it — and the face is now the one Conduit itself uses for the same job.
  Consumers: `.num`, `code`, `.raw`, `.eyebrow`, `.step-n`,
  `#wizard-nav .count`, `.ribbon .item .badge` (700, a notification idiom, not a
  mono decision), `th.num` (600, the table-header weight).
- **Eyebrows follow the site's mono treatment**: `--font-mono`, uppercase,
  `--fs-micro`, **weight 500**, line-height 1, **letter-spacing 0**. The site's
  `.subheading` is not tracked — the mono face and the uppercase are what mark
  an eyebrow — so `--ls-eyebrow` is 0 and the lowercase-sans-at-0.14em eyebrow
  the console invented is retired. It is 500 rather than the 400 the site's rule
  *writes*, for the reason under Weights below. The accent colour stays
  (5.59:1 on paper, 5.19:1 on `--surface`; it is a label, not a link).
- **Scale** (CSS custom properties, rem) — sizes unchanged, and they turn out to
  sit on the site's own steps:

  | Token | Size | Use | Site's step |
  |---|---|---|---|
  | `--fs-micro` | 0.6875rem (11px) | Table headers, micro-labels, eyebrows | `--font-size--subheading` 0.7rem |
  | `--fs-xs` | 0.75rem (12px) | Meta lines, correlation ids, table captions | — |
  | `--fs-sm` | 0.8125rem (13px) | Help text, pills, badges, result-meta | `--font-size--body-small` 0.8rem |
  | `--fs-table` | 0.875rem (14px) | Table cells | — |
  | `--fs-base` | 0.9375rem (15px) | Body, forms, nav | `--font-size--body-regular` at ≤479px = 15px |
  | `--fs-md` | 1.1875rem (19px) | Section headings (h2) | — (the site has no small-heading idiom) |
  | `--fs-lg` | 2.875rem (46px) | Page titles (h1) | `--font-size--h4` 2.9rem |

  Line-height: **1.2 on h1**, 1.0 on h2 (the site sets 1 on h2–h6 and .9 on its
  128px h1), 1.45 body, 1.35 in tables. Two deliberate departures from the site,
  both because this is an app and that is a marketing page:
  - **Body 1.45 against the site's 1.1** — 1.1 is display-copy leading, and this
    app is read as paragraphs, help text and table rows.
  - **h1 1.2 against the site's 1** — the site's headings never wrap; five of
    this console's h1s are a name it was handed (`customers/detail`,
    `contacts/edit`, `accounts/detail`, `orders/detail`,
    `transactions/detail`), and at 900px a real German company name runs to
    three lines. Measured in the browser at 46px DM Sans, an accented cap
    reaches 41.4px above its baseline and a comma-below 10.9px under the line
    before it, so the baseline step must clear 52.3px: 1 gives 46px (**−6.4px,
    the lines overlap**), 1.1 gives 50.6px (−1.8px), 1.15 gives 52.9px
    (+0.5px, touching), 1.2 gives 55.2px (+2.8px). 1.2 is the first value that
    clears; the cost is 9px on a single-line page head.
  Tracking tokens: `--ls-h2` 0.04em (the console's own uppercase display device
  — h2 **and the brand mark**), `--ls-micro` 0.1em (uppercase *sans*
  micro-labels), `--ls-eyebrow` **0** (Conduit's). **h1 letter-spacing is 0** —
  the site tracks Founders Grotesk at 0 from 25px to 128px without a single
  adjustment, and the console's -0.015em was compensation for Archivo's 800.
- **Weights:** 400 body **and h1** (the site sets *every* heading at 400), 500
  labels/nav-active, `--fw-display` **and the whole mono layer**, 600 buttons
  and table headers, 700 the environment badge and the ribbon's count badge.
  `--fw-display` is **500** — Medium, the heaviest weight Conduit's site loads
  of its heading face. The 800 was Archivo's and retired with it; nothing set in
  `--font-heading` is heavier than 500, and the two 700s are DM Sans and
  JetBrains Mono, which both really have it.
  **Mono is 500, not the 400 the site's rules write.** Read the site's
  `@font-face` block before its rules: conduitpay.com loads exactly one cut of
  JetBrains Mono, `JetBrainsMono-Medium.woff2` at 500, so every mono declaration
  there — `.subheading`'s `font-weight: 400` included — resolves to Medium
  whatever number is next to it. Copying the number instead of the rendering is
  how you end up lighter than the thing you are matching. It costs nothing:
  JetBrains Mono's advance is fixed across the `wght` axis (the same 25-character
  id measures 218.3998px at 14px on 400, 500 and 600), so no ledger column moves.

## Color

- **Approach:** restrained, and green-biased rather than cool.
  One accent ramp, one exception red, one amber outlier, and neutrals mixed
  toward the ink so nothing on screen is a colour by accident.
- **Ink (text and the primary action):** `--ink: #103020`. Primary buttons are
  ink-filled and hover to `--accent-700`; **the forward action is not a hue**
  (see an earlier round section). Links: `--link: var(--accent-700)` (#0a5228,
  9.33:1 on paper), hovering to `--accent-500`.
- **Accent ramp** (`--accent-100` … `--accent-900`, `--accent` = the 500):
  `#eaf6ee · #cfe9d8 · #a6d6b8 · #5fb681 · #087838 · #076a31 · #0a5228 ·
  #0d3f22 · #103020`. The 900 *is* the ink: the ramp ends where the text
  begins, which is why an ink-filled button and an accent-filled pill never
  look like two different systems.
- **Neutrals (green-biased):** `--paper: #ffffff`, `--surface: #f4f7f5`,
  `--surface-2` = 8% ink on paper (readonly boxes),
  `--neutral-600 #6c7d72` (**borders and rules only — 4.36:1, not text**),
  `--neutral-700 #55655b` = `--muted` (secondary text, 6.18:1),
  `--neutral-800 #35473c`.
  `--divider` = `color-mix(in srgb, #103020 28%, transparent)` and
  `--divider-soft` = the same at 14%. `--line` / `--line-soft` are kept as
  aliases of those two, so every existing consumer resolves unchanged.
  `--rule: 2px solid var(--divider)` is the **structural** device — the header's
  bottom edge and a table head's bottom edge — with 1px hairlines inside it.
- **Semantic status — five states, four visual families** (each a fg/bg/line
  triple; the *line* is no longer always the fg):

  | State | Fg | Bg | Line | Meaning (strict) |
  |---|---|---|---|---|
  | `ok` | `--accent-700` | `--accent-100` | `--accent-400` | Terminal success |
  | `warn` | `#8a5a00` | `#fff8e6` | `#8a5a00` | Needs a human (RFI, stalled, review) |
  | `bad` | `#b00020` | `#fdedf0` | `#d78c98` | Terminal failure / error |
  | `wait` | `--ink` | *transparent* | `--divider` | In flight, resolving without you |
  | `neutral` | `--muted` | `--surface` | `--neutral-600` | Unknown/unmapped enums, drafts |

  `ok`, `bad` and `wait` are DESIGN_DIRECTION.md's three pill families
  verbatim. `warn` is the fourth, and it is deliberately the one hue the
  imported direction has no answer for — see the Decisions Log. The *rule* is
  unchanged: never use a status hue for anything that isn't that state, and an
  unknown enum value always renders `neutral` (spec §7).
- **The exception family is `bad` and nothing else.** `#b00020` and its tints
  may dress a terminal failure, a problem-detail box, a destructive button's
  outline, and a row-left flag. Never a selection, never an
  affordance for something that has not gone wrong.
- **Dark mode:** not in v1. Single committed light look; revisit only on
  operator request.

## Spacing

- **Base unit:** 4px. Scale as custom properties:
  `--sp-1: 0.25rem` · `--sp-2: 0.5rem` · `--sp-3: 0.75rem` ·
  `--sp-4: 1rem` · `--sp-6: 1.5rem` · `--sp-8: 2rem`.
- **Density:** compact. Tables `--sp-2 --sp-3` cell padding; forms
  `--sp-3` between fields within a group, `--sp-6` between groups; page
  sections separated by `--sp-6`.

## Layout

- **Approach:** a two-column page shell — the left menu ribbon (`13rem`) and
  the content column, laid out as a grid on `body` itself. Content is a single
  column, `max-width: 85rem` (1360px) main. Detail pages may use a two-column
  definition grid (`label | Value`). Under `60rem` the ribbon turns on its side
  into a wrapped band above the content; there is no collapse mechanism.
- **Border radius:** `--r-sm: 6px` inputs/badges, `--r-md: 8px` cards/flash/
  problem, `--r-lg: 12px` the largest surfaces; **every control — button, tag,
  chip, segment — is `--r-pill: 999px`** (imported values, from
  DESIGN_DIRECTION.md).
- **Tables:** compact rows, `--line-soft` separators, header row `--fs-xs`
  uppercase `--muted` with `--line` bottom border, row hover `--surface`.
  Numeric/id columns right-aligned monospace. Empty states are a sentence
  plus the one action that fills the table, never a bare "No rows".

## Motion

- **Approach:** minimal-functional. One duration, one easing:
  `--t-fast: 120ms ease-out` for hover/focus and htmx request indicators.
  No entrance animations, no transitions on layout properties. htmx
  in-flight state: source control dims (`opacity .6`) + `cursor: progress`
  via `.htmx-request`; long requests get an explicit inline indicator.
  `prefers-reduced-motion` disables the lot.

## Safe choices vs. deliberate risks

Safe (category baseline): restrained near-monochrome palette; grid
discipline; system font stack; semantic green/amber/red/blue statuses.

Risks (where this console gets its face):
1. **Denser than modern SaaS** — 13px tables, 14px body, compact padding.
   Operators scan; whitespace-per-row is cost, not luxury.
2. **Color = state, nothing else.** No colored links in chrome beyond
   `--link`, no decorative accents. A colored word always means money-state.
3. **Monospace as identity.** Everything machine-generated (ids, amounts,
   IBANs, timestamps) in the mono stack — the console reads like an
   instrument, and a wrong digit is visible.

## 2026-08-29 refresh — Wise × Apple

Direction: "a mix of Wise and Apple — clean and very
intuitive, yet appear sharp." Applied as a refinement of the system above,
not a replacement; everything not named here stands.

- **Interactive identity (Wise):** a deep forest green becomes the color of
  *interaction* — `--brand: #14301f` (primary buttons, links, active nav),
  `--brand-strong: #0e2416` (hover), `--accent: #9fe870` (focus rings,
  selected-chip fill with ink text). The color rule is now two-sided:
  **brand green = you can act here; status hue = the state of money.** The
  `ok` status green (`#0f7b3d`, always a pill/flash tint, never a control)
  and the brand green never appear in the same role, so they cannot be
  confused. `--link` becomes the brand green; `wait` keeps its blue.
- **Buttons (Wise):** pill-shaped (`--r-pill: 999px`), `--fs-base`, 500
  weight, `.45rem 1.1rem` padding. Primary = brand fill, paper text.
  Secondary = paper fill, hairline border, ink text. Danger stays outlined
  `--bad`, now also pill. One primary per page, unchanged.
- **Surfaces (Apple):** page stays paper-white; cards and filter bars get
  `--shadow-1: 0 1px 2px rgba(22,32,42,.05), 0 0 0 1px var(--line-soft)`
  instead of a heavier border — depth by hairline, never by gray fill.
  Radii sharpen to `--r-sm: 6px` (controls) and `--r-md: 10px` (cards).
- **Type (Apple):** headings tighten — h1 `1.375rem/600` at `-0.015em`,
  h2 at `-0.01em`; body and table sizes unchanged (density is an operator
  feature, and "clean" is spent on chrome and forms, not on rows).
- **Forms (Apple):** inputs grow to `.5rem .65rem` padding, `--r-sm`,
  hairline border, and a two-layer focus: `--accent` ring outside a brand
  border. Labels stay 500.
- **Nav (Apple):** the active item becomes a quiet pill (`--surface` fill,
  600 weight) instead of an underline; hover shows the same pill at lower
  emphasis.
- **Texture:** the page stays
  paper, but components stop sharing its plane. `--surface-2: #eef1f3` joins
  the neutrals as the *component* tint. Table header rows get a `--surface`
  band (full-bleed within the table, hairline below). Filter/prefill bars
  get `--surface` fill with a hairline ring — a tool tray, distinct from
  white content cards. Form controls get a faint `--surface` fill at rest
  that turns paper on focus (the field "lights up" under the caret), and
  selects draw a muted chevron as an inline SVG data-URI so a dropdown is
  visibly a dropdown before it is clicked. No images, no gradients heavier
  than the existing hairline shadow.
- **Constraints unchanged:** no webfonts, no build step, one CSS file, no
  new dependencies. The awesome-ui-libraries repo surveyed for this pass is
  a link list of React/Tailwind ecosystems — used as inspiration only;
  nothing vendored.
- **Superseded 2026-08-31 by an earlier round section below.** `--brand`,
  `--brand-strong` and the `#9fe870` accent no longer exist; the two-sided
  "brand green = you can act" rule and the two-layer focus ring are both
  replaced. The webfont clause is the amended one under Typography. Everything
  else in this section — pill buttons, hairline surfaces, taller inputs, the
  quiet nav pill, the `--surface` texture pass — stands.

## 2026-08-31 refresh — imported design direction

Source: `DESIGN_DIRECTION.md`, the implementable distillation of the
commissioned designer canvas. The first slice is the **token layer only** — palette,
type, radii, rules, the vendored face, and the status families. Page structure
(eyebrows, stat bands, chrome, list patterns, the drawer) is slices 2–6;
nothing here restyles markup that does not already exist.

- **Type is Archivo**, vendored (see Typography). H1 46px/800, H2 19px/800
  uppercase at 0.04em, body 15px, table cells 14px, table heads 11px uppercase
  at 0.1em. Mono stack untouched — it is still the console's signature and
  still where every machine-facing value is set.
  **Superseded 2026-09-02.** The *sizes* in this row all survive —
  46px, 19px, 15px, 14px, 11px, and both tracking values are unchanged. The
  face and the weights do not: Archivo is deleted, H1 is 46px/**400** at
  letter-spacing **0**, H2 is 19px/**500**, and the mono stack is no longer the
  system's — it is JetBrains Mono, which is Conduit's. See Typography.
- **Palette is the accent ramp** (see Color). Ink `#103020`, surface `#f4f7f5`,
  accent `#087838` with a 100–900 ramp, green-biased neutrals, and a
  `color-mix` divider at 28% ink.
- **The forward action is ink, not a hue.** the rule was two-sided
  (brand green = you can act, status hue = the state of money). It cannot
  survive this palette, because the direction's accent green *is* the ok-status
  green. So the rule moves: **ink = the thing you press; accent = affirmative
  state, or which view you are looking at; `#b00020` = an exception; amber =
  needs a human.** Every green on screen is once again only ever about state or
  about where you are — the ambiguity once solved with a second green is now
  solved by taking action off colour entirely.
- **Selection wears `--accent-200` with `--accent-900` text** — the direction's
  tab pattern — on `.btn.selected`, `.segmented` and `.pill-group`. Its border
  is the **500**, not the ok-pill's 400: see the Decisions Log.
- **Focus is one 2px `--accent` ring again**, offset 2px, replacing the
  two layers. `#087838` is 5.59:1 on paper where `#9fe870` was 1.47:1, so the
  inner contrast-carrying band it needed no longer has a job.
- **2px rules are structural**, 1px hairlines are internal. Applied in this
  slice to the two structural borders the current markup already has: the
  header's bottom edge and a table head's bottom edge.

## 2026-09-03 — Arca direction — A1 (tokens + theme)

Source: `docs/ARCA_REVAMP_SPEC.md` §1, §3, §9, under an earlier round
type ruling. This slice replaces the token layer and adds the dark theme;
**the Color section and the Layout section's radius line above are superseded
by it** and are left as the record of what shipped.

- **Three grounds, not two.** `--page` (the window) is new and joins `--paper`
  (what text sits on) and `--surface-2` (the inset step). `body` takes
  `--page`; the shell that will carry `--paper` comes later, so today the two
  are one step apart in light and the whole page is the window in dark.
  `--surface` — the tray/hover step — is a fourth value in dark rather than the
  spec's copy of `--paper`; see the Decisions Log row, and note that in **light**
  it equals `--page` on purpose and therefore shows nothing until A2 lands the
  shell.
- **The palette is cool, not green-biased.** `--ink #0b0e14`, `--muted
  #475569`, `--accent #3355ff`. The accent ramp (`--accent-100`…`900`) and
  `--neutral-800` are deleted; `--ok` and its tints are their own hexes rather
  than borrowed rungs of the ramp, which is what made the accent and the
  ok-status green the same colour in the first place.
- **Dark ships, in two hand-duplicated selectors.** `@media
  (prefers-color-scheme: dark) :root:not([data-theme="light"])` and
  `:root[data-theme="dark"]`, carrying identical values. The `:not()` guard is
  what lets an explicit *Light* beat a dark system preference, which a single
  combined selector list cannot express; `tests/test_contrast.py` asserts the

## 2026-09-03 — Arca direction — A3 (failure paths)

The two findings the spec ranks **blocking** (§0.2), and the one that makes a
refusal legible to somebody who cannot see the red box. Nothing about the
operations ledger, `request_hash`, idempotency or what is sent to Conduit
changes in this slice: it only changes what an operator READS.

- **Failure paths are pages.** `403`, `404`, `500` — and, because
  `app/web/exports.py` alone raises a dozen of them, `400` and `409` too —
  render `error.html`, which extends `base.html`. One template, not three:
  the only thing that differs is a heading and a sentence (`web.ERROR_COPY`),
  and three files would be three places for the chrome and the way back to
  drift. Every one of them is *inside the ribbon*, carries the right status,
  and offers exactly one way on (the Overview) plus the browser's own Back —
  a page that guesses ten destinations reads as a page that does not know.
  The middleware's own 403 (a CSRF refusal, an account mapped to no role)
  joins them: it was a bare `<h1>` on white, which is the same framework
  default showing through one surface nobody styled.
- **The failure pages state nothing about the machine.** No exception text,
  no traceback, no path, no host, no key, no request body. A 403 **does** name
  the permission — the gate's ruling, reversing the first cut: an operator who
  cannot tell an administrator which action to grant is stranded on the page
  that exists to unstrand them, and the gate names are already in
  `PERMISSIONS.md` and every deployment's `ROLES_FILE`. Which roles hold it,
  and who does, are still never named. The 500 carries **one**
  thing: a twelve-character reference minted per request and logged beside
  the traceback, so an operator has a token to quote to whoever runs the
  install. It is deliberately *not* Conduit's `correlationId`: the client is
  process-wide and holds no request, and Starlette runs the 500 handler
  outside the middleware that would carry one — an honest console id beats a
  correlation id that would be right only sometimes.
- **The 500's sentence does not claim safety.** "This page cannot say whether
  what you pressed took effect — open the record and read it before repeating
  anything that moves money." A failure page that says *nothing happened* is
  the console lying about the state of money in the one moment it cannot know.
- **Upstream problems are translated at ONE boundary**, and that boundary is
  `conduit.parse_problem` — the single place an error body becomes a
  `Problem` in this process. `title` and `resolution` come from
  `app/conduit/problems.py`, keyed by Conduit's machine code; `detail` is
  dropped to `""`. Doing it here rather than in the templates is the whole
  point: seven call sites render `result.title` (two of them `result.detail`)
  straight into a flash banner, a CSV note or a batch report, and a fix at the
  render layer would have left every one of them open. **The code stays on
  screen** and `Problem.type` is untouched — it is what a support conversation
  quotes, and what the reconciler's `DEFINITIVE_CONFLICTS` matches on.
- **The evidence is untouched.** `Problem.raw` still holds every byte Conduit
  sent and is still what `operations.error` stores. The replay path
  (`web.problem_of`) therefore translates too, through the same table, and a
  snapshot this console minted itself keeps its own words rather than being
  printed as a refusal Conduit never made (`problems.MINTED_HERE`). **Every
  reader of `Operation.error` goes through it** — the gate found five that did
  not (the batch detail cell and the results CSV, the revoke and cancel
  banners, the order execute banner, and the upload chip), each lifting the
  stored `title` or `detail` straight out of the snapshot, and a grep pin over
  `app/web/*.py` and `app/batches.py` now fails on the sixth.
- **Unknown codes are named, not narrated.** Anything the table has no
  sentence for renders `Conduit refused this: {code}`, plus Conduit's
  `resolution` line if it sent one — for a refusal this console cannot
  explain, that line is the only remaining guidance and is at least
  action-shaped. Conduit's `detail` never appears, under any code.
- **Field errors are bound to their fields.** `aria-invalid="true"` and
  `aria-describedby="{field}-error"` on the control — on *every* input of a
  radio or checkbox group, because those two widgets have no single element
  carrying the field's id and a description on a wrapper `<div>` is never
  announced. The error box gets one id however many sentences it holds. Done
  in the macro, so `forms.py`, `html_attrs` and the mapper are byte-identical
  and FORM_ENGINE_SPEC needs no amendment; a field with no error renders
  exactly as it did before. An error whose pointer matches no rendered field
  is still listed once under the form (the mapper already never dropped one —
  what A3 adds is the pin that it appears once, not twice).
- **Existing console sentences are untouched.** `payments.payout_errors`,
  every `local_problem` caller, the `rejection` macro's `failureCode`
  translation: those already speak in this register, which is the proof the
  register was never the problem — only the pass-through path was.

## 2026-09-03 — Arca direction — A5 (long tail + the shared table scroll-wrapper sweep)

Source: `docs/ARCA_REVAMP_SPEC.md` §3.5, §4.1, §5, §6, under the
A5 addendum (2026-09-03). Two mandates: the
one shared table scroll-wrapper, owed since A2/A4 found the overflow and
deferred it here; and a re-skin pass over everything A1/A2/A4 did not already
touch — `onboarding/`, `batches/`, `payouts/`, `drafts.html`, `operations/`,
`rfis/`, `contacts/`, `accounts/`, `convert/`, `orders/`, `recipients/`,
`applications/`.

- **The wrapper decision, measured before it was written.** The addendum
  named the fork explicitly: an always-on `.table-scroll { overflow-x: auto }`
  if a sticky table head survives being wrapped in one, or a width-gated
  version if it does not — "measure it" rather than assume either way. A
  standalone reduction (a table with this stylesheet's own sticky rule,
  `tr:not(:has(td)) { position: sticky; top: 0 }`, wrapped in an always-on
  `overflow-x: auto` div, driven in a real browser) answered it: `position:
  sticky` sticks to the nearest ancestor that **establishes a scroll
  container**, not to the viewport, the moment that ancestor's overflow stops
  being `visible` — and the wrapper has no height of its own (it is exactly
  as tall as the table it holds), so it never scrolls internally. Scrolling
  the *page* past it, the header did not hold at the top of the viewport; it
  scrolled away with row 0, exactly like an ordinary block. An always-on
  wrapper would have fixed the overflow this slice was sent to fix by
  quietly breaking the sticky head shipped on every list in the
  console, at every width, including the 1440px desktop session where
  nothing was broken before this slice touched it.
  So the wrapper is conditional: `.table-scroll` is a no-op div above
  1024px and takes `overflow-x: auto` at and below it — `@media (max-width:
  1024px)`, one query, one rule. 1024px is not a round guess; it is the
  widest of the three widths DESIGN.md's A4 row measured the pre-existing
  overflow at (`/` 380px at 375, `/customers` 584px, `/transactions` 922px at
  375/768 and 1130px at 1024), and 1440 is the one width that row found
  clean, so nothing above 1024px has to give sticky up to fix an overflow
  that was never there. Pinned two ways: `tests/browser/test_a5_table_scroll.
  py::test_the_wrapper_only_scrolls_below_the_width_tables_overflow_at`
  reads the computed `overflow-x` at both sides of the boundary, and
  `test_sticky_head_survives_above_the_wrapper_width_and_the_page_still_does_not_overflow_below_it`
  proves the trade in a real scroll: the header still tracks the viewport at
  1440 (the same proof `test_the_column_headers_stay_put_when_a_long_list_
  scrolls` already carried at the suite's default, wider-than-1024 viewport)
  and the document itself carries zero horizontal overflow at 768.
- **The idiom is the wrapper element, not a macro — there was no table
  macro to add it to.** `macros.html` has no `table()` macro; every list
  page hand-writes its `<table>`, which is the reason A2/A4 found this
  overflow and could not fix it in three pages without leaving the other
  twenty-four still broken. Adding a macro now would still touch every call
  site (a macro invocation costs the same edit as a wrapper `<div>`, since
  the surrounding markup — cards, forms, conditional blocks — is not
  uniform enough to fold into a shared macro's parameters without inventing
  one just for this), so the smallest idiom is literally the div: `<div
  class="table-scroll">` immediately before every `<table`, `</div>`
  immediately after every matching `</table>`. Applied uniformly to **every**
  `<table>` in the templates rather than only the ones observed to overflow
  today — a definition-row table (`<th>label</th><td>value</td>`, two
  columns, never wide enough to trigger the media query) costs nothing to
  wrap and one fewer judgment call than deciding site by site which tables
  "count" as list tables. **44 sites, 27 templates** (`grep -rc '<table'
  app/web/templates` before and after this slice: same count, now each one
  preceded by the wrapper), enumerated in the phase report. Pinned
  statically over the template source rather than the rendered page —
  `tests/test_table_scroll_wrapper.py` — because the question ("is this
  literal tag preceded by the wrapper div") is the same either way and a
  static grep needs no fixture for any of the 27 templates' wildly different
  data shapes.
- **The re-skin found almost nothing to re-skin.** Every retired
  token (`--r-pill`, `--accent-700`, `--divider`/`--divider-soft`,
  `--processing`) is gone from the long-tail templates by grep, as it is
  everywhere else — they were stylesheet-only names, never written into a
  template. No hard-coded hex colour, no inline `style` carrying a colour or
  a weight, no `font-weight: 700/800` literal, no uppercase `<h2>`, no
  accent-coloured `.eyebrow`, no old-shape status pill bypassing `m.
  statuspill`/`.pill`, no `.help` misuse turned up across `onboarding/`,
